# 待办任务 (dsh-task-todo)

当用户提到「待办 / 任务 / 清单 / 安排日程 / 提醒我做什么」，或需要读取、新增、完成、
推迟、重复安排任务时使用本技能。

任务数据是**全局**的（不按会话或工作区分库），存放在 `<DSH_HOME>/todo/tasks.json`。
浏览器端有一个完整的界面（侧边栏「待办任务」入口，支持列表 / 看板 / 日历 / 甘特四种视图），
你与它共享同一份数据。

## 工具

| 工具 | 用途 | 关键参数 |
| --- | --- | --- |
| `task_list` | 查询任务 | `filter`(today/week/overdue/inbox/all/done)、`list`、`query`、`tag`、`includeDone`、`includeSubtasks` |
| `task_add` | 新建任务或子任务 | `title`、`due`、`start`、`priority`(0-3)、`list`、`tags`、`note`、`repeat`、`repeatInterval`、`repeatWeekdays`、`repeatUntil`、`repeatCount`、`parent` |
| `task_update` | 修改任务 | `id`（也可用唯一标题）、任意可改字段；`repeat: ''` 取消重复 |
| `task_done` | 完成 / 取消完成 / 推进重复任务 | `id`、`undone` |
| `task_delete` | 删除任务（连同子任务） | `id` |
| `list_manage` | 管理清单本身：列出 / 新建 / 改名 / 换色 / 排序 / 删除 | `action`(list/create/update/move/delete)、`id` 或唯一清单名、`name`、`newName`、`color`、`index`、`delta` |

`id` 既接受系统生成的 id，也接受**唯一**的标题；标题不唯一时会拒绝并返回候选，
不会猜。所以先 `task_list` 再改名，比直接猜 id 可靠。

`list_manage` 同理接受唯一的清单名。它删的是**分组**，不是任务：清单里的任务会移到
「收集箱」，系统清单「收集箱」删不掉。`index` 是目标位置（0 = 最前），`delta` 是相对位移
（-1 上移一位）。顺序会影响看板列的先后，也会影响界面左栏。

## 日期与重复约定

- 日期一律用**本地日历字符串**：`YYYY-MM-DD`（全天）或 `YYYY-MM-DDTHH:mm`（定时）。
  不要传 `Date` 对象或时间戳。
- 重复：`repeat` 取 `daily` / `weekly` / `monthly`；`repeatInterval` 是间隔（每 N 天/周/月）；
  `repeatWeekdays` 只在周重复时使用，**0 = 周日 … 6 = 周六**；结束条件用 `repeatUntil`
  （日期）或 `repeatCount`（次数），二者不同时使用。
- 完成一个重复任务**不会**把它标记成完成：它记录一次完成、把截止时间滚动到下一次、
  并把子任务重置为未完成。这由宿主负责，你只要调用 `task_done`。
- 月初/月末的「每月 31 日」这类规则从**系列锚点**推算，不会逐次累积漂移。

## 学习模式

当用户用 `/todo` 加上一句「我想学 / 我要学 X」，或直接说「记个学习计划：X」时，进入学习模式。
它的产物是**一条课表**：一个清单 + 一个父任务（课程）+ 若干子项（课时，按顺序推进）。

`/todo` 后面的整句都当**目标**收下，不做参数校验——`/todo 我要学 Python 处理 Excel`
里的每个字都是目标的一部分。

### 四条契约

1. **一次一清单**。一次会话最多新建一个清单，名字 `学习·<目标短语>`。
   已经存在同目标清单时**不要新建**：把新内容追加进去，并告诉用户加进了哪条。
2. **先提案，后落库**。先用 3~5 行给出一份紧凑课表，再等用户明确同意（「好」「落」「可以」）
   才真正创建。**不要默默建清单，不要边聊边加条目。**
3. **不排日期**。课时的 `start` / `due` 一律不设（显式传 `null`），父任务的 `note` 写
   「按顺序推进，不排日期」。默认日期套上来会让 12 课全落在今天，清单当场作废。
4. **首轮上限 12 条**，一个模块最多 4 课。真需要更多就分模块、开第二轮，不在第一轮塞满。

### 提案的形式

```
学习·Python 处理 Excel
  1. 跑通第一个读写脚本 · 交付：脚本能读入 xlsx 并另存为新文件
  2. 单元格与区域定位 · 交付：能按行列号与名称取值
  ...
```

一行一课：`标题 · 交付：<一句可验收的产物>`。交付物是必须的——没有交付物的条目
无法验收，只是气氛。落库时把这一句写进该子项的 `note`。

### 落库怎么调工具

不新增工具，复用现有的：

1. `list_manage` `action=create` 建 `学习·<目标短语>` 清单；
2. `task_add` 建父任务（标题＝目标，`note` 写「按顺序推进，不排日期」）；
3. `task_add` 依次建子项，`parent` 传父任务 id 或标题，`note` 写交付物，**不传 `due`/`start`**。

顺序就是子项的创建顺序，界面上的「当前课时」由**第一个未完成的子项**推导，不需要额外字段。

### 之后的日常动词

| 用户说 | 你做什么 |
| --- | --- |
| `继续学` / 下一课 | 读该清单里第一个未完成的课时，**直接开始讲那一课**，不复述进度、不再确认 |
| `学完了` | 把当前课时 `task_done`，焦点自动落到下一课，一句话报进度 |
| `跳过这课` | 同样 `task_done`，并在该子项 `note` 追加一句「跳过」；不要为跳过新增状态 |
| `加一课：X` | 追加到父任务末尾——**这一条允许免提案**，其余情况都要先提案 |

### 目标太大时

只在「学数学」这类宽泛目标上反问**一次**：给 2~3 个具象方向让用户挑一个。
不要同时追问基础、时长、深度——要一次问完就不是模式了。

### 不做

打分 / 测评、闪卡、按遗忘曲线自动建复习任务、按周自动摊平日期、自动把课时打勾。
这些要么是产品野心，要么会污染用户的清单。

## 快速添加语法（自然语言）

`/todo add <文本>` 和界面上的快速添加框都走同一个解析器：

```
明天 15:00 交周报 !高 #工作 @紧要
每天 9:30 晨会
每周一三五 健身
每月5日 交房租
下周三 见客户
2026-10-01 国庆安排
```

- 优先级：`!高` / `!中` / `!低` / `!1`~`!3`
- 标签：`@标签`
- 清单：`#清单`（不存在时自动创建）
- 重复：`每天`、`每周一三五`、`每月`、`每 2 天`、`每月 5 日`
- 时间：`上午/下午/晚上 9点`、`9:30`、`15:00`

## 斜杠命令

| 命令 | 行为 |
| --- | --- |
| `/todo` | 今天的概览（今天到期 + 已逾期）；即使用户只打了 `/todo` 也有输出 |
| `/todo <学习目标>` | 进入**学习模式**：先出课表提案，同意后建 `学习·<目标>` 清单 |
| `/todo add <文本>` | 用快速添加语法新建任务 |
| `/todo ls [筛选]` | 列出任务，筛选支持 今天 / 本周 / 逾期 / 未安排 / 全部 / 已完成 |
| `/todo done <id或标题>` | 完成（重复任务则推进到下一次） |
| `/todo help` | 语法速查 |

## 与其他能力配合

- 需要把正文、会议记录里的行动项落成任务时，先 `task_list` 看有没有同名任务，
  再 `task_add`，避免重复创建。
- 任务的备注（`note`）适合放上下文（链接、结论、验收标准），子任务的备注同样可用。
- 提醒 / 系统通知目前**不在 v1 范围内**：不要承诺到点弹通知，只承诺任务被记录并在
  界面中按日期呈现。

## 边界

- 清单（list）是真实分组；今天 / 本周 / 逾期 / 未安排 / 已完成是**虚拟智能清单**，
  由查询的 `filter` 参数表达，不要试图把它们建成清单。
- 清单的颜色只有 8 个预设（界面里是色板，点一下即生效）。`list_manage` 的 `color`
  也应当是这几个之一，别自己发明配色；颜色是给人一眼分辨的标签。
- 看板视图的列就是清单，顺序跟着清单顺序；日历视图按 `due` 排布，重复任务在每个发生日都会出现。
- 甘特图使用 `start`（起点，可空）到 `due`（终点）的区间；只有 `due` 的任务是单日条目，
  两者都没有的任务不会出现在甘特图中。
